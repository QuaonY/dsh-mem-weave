# 架构与工作机制

记忆如何分层、每轮注入什么、检索怎么走、数据落在哪。使用与配置见 [USAGE.md](./USAGE.md)，隐私边界见 [PRIVACY.md](./PRIVACY.md)。

## 1. 整体结构

```
DSH 宿主
 ├── src/host      插件入口、服务、RPC（界面用）、22 个 weave_* 工具（AI 用）
 ├── src/core      渲染、分词、打分、日历与文案组装
 ├── src/store     SQLite、写入治理、检索、向量、整理（dream）、备份
 ├── src/privacy   敏感信息检测与脱敏
 ├── src/presets   内置人格
 └── src/client    九个界面页面（React）
```

宿主只加载 `lib/index.js`；界面在 `lib/client.js`，React 由宿主注入。两者都由 `scripts/build.mjs` 用 esbuild 打成单文件。测试与召回基准在 `test/`（基准套件 `test/bench`），不随包分发。

## 2. 记忆的七个层

| 层 | 放什么 | 半衰期（默认） |
| --- | --- | --- |
| `soul` | 关系状态 | 365 天 |
| `user` | 用户的偏好、习惯、身份 | 365 天 |
| `rules` | 必须遵守的规则（人工写入） | 不衰减 |
| `project` | 项目约定与进展 | 180 天 |
| `fact` | 客观事实 | 90 天 |
| `lesson` | 踩过的坑、被纠正的做法 | 365 天 |
| `topic` | 话题与整理出的摘要 | 30 天 |

每条记忆带 `status`（`active` / `stale` / `merged` / `archived`）、`importance`、`valid_from` / `valid_to`、`semantic_key`、`evidence` 与链接关系；状态只决定是否参与注入与检索，不改写原文。

## 3. 三段注入

| 段 | 时机 | 内容 | 默认上限 |
| --- | --- | --- | --- |
| S1 人格 | 每轮 | 人格正文 + 思考语言 + 后缀，9 个块按固定顺序拼接 | 由人格长度决定 |
| S2 快照 | 会话第一轮 | 你是谁、规则、关系、进行中的项目、用户画像摘要 | 4000 字 |
| S3 增量 + 召回 | 之后每轮 | 新增/改动的记忆 + 与本轮话题相关的记忆 | 1200 + 900 字，最多 5 条 |

块顺序固定、缺块不留空行；超限按优先级裁剪并写入 `inject_state`（界面「注入与预算」可核对）；注入前统一清理特殊括号与换行，防止伪造段落。

## 4. 检索流水线

```
FTS5 前置候选（分词串，中文按二元组）
  → 关键词(BM25) ┐
  → 语义(可选)   ┼→ RRF 融合(k=60) → 时间衰减(带下限) → 去同质 → 反刍抑制 → top-k
  → 链接扩展     ┘
```

- 权重默认：关键词 1.0、语义 0.8、链接 0.5（`recall.weights`）；`importance` 只在主分数相同时作 tie-breaker。
- 结果带 `trace`（命中原因、衰减系数），界面「记忆 → 检索解释」可见。
- 语义路需三者齐备：界面「高级」的向量开关（存记忆库）、embedding provider（配置 `embedding` 或环境变量）、后端可用；任一环缺失只走关键词。启动时只探测本机 `127.0.0.1` 的 Ollama / LM Studio，`MEMWEAVE_EMBEDDING_DISCOVERY=0` 可关闭。

### 向量后端

| 后端 | 说明 |
| --- | --- |
| `sqlite-vec` | 原生扩展，五平台预编译二进制随包分发（`lib/native/`） |
| `vectra` | 纯 JS HNSW，本体随包放在 `lib/vendor/` |
| `builtin` | 兜底：SQLite BLOB 存向量 + JS 余弦暴力检索 |
| `disabled` | 仅当 `MEMWEAVE_VECTOR_BACKEND=off` |

加载顺序 `sqlite-vec → vectra → builtin → disabled`；任一环失败都退回关键词召回。探测结果会缓存，恢复备份后自动重新探测，避免旧缓存让检索失效。

## 5. 写入治理

AI 写入要过四级把关：

1. **来源检测**：区分明说、观察、推断；推断内容置信度低、可过期。
2. **去重与合并**：语义键相同或高度相似的条目合并，保留证据链。
3. **冲突冻结**：互相矛盾的内容冻结为候选，等人裁决，不覆盖旧结论。
4. **审计与撤销**：写入、修改、合并、整理都留审计记录，24 小时内可撤销。

`rules`、`soul`、人格、永久删除的操作，无论界面还是工具调用都要求人工确认。

候选按风险分级：低风险自动接受（`governance.autoAcceptLowRisk`），高风险留待人工确认；冲突合并同样走这条治理管线，不绕过分级。

## 6. 遗忘与整理（dream）

遗忘只改排名、不删数据：半衰期按层设置，常用条目最多延长 8 倍；时间衰减带下限（`lifecycle.decayFloor`，默认 0.1）；同话题条目反复命中会被降权。

整理在空闲时进行（默认空闲 180 分钟）：

- 过期条目转 `stale`；
- 长期未用的零散条目按项目分组合并为摘要（`merged`，原文可恢复），不跨项目混合；
- 完工超过半年的项目整体归档（`archived`，原文可恢复）；
- `rules`、`user`、`soul` 与未到期约定永不归档。

多进程打开同一个库时，`process_lease` 选出唯一持有者执行整理与向量索引，其余进程照常读写；租约 TTL 180 秒。

## 7. 数据存放与备份

| 路径 | 内容 |
| --- | --- |
| `<dataDir>/memweave.db` | 主库（单文件 SQLite，schema v15） |
| `<dataDir>/mirror/` | 人类可读的记忆镜像（Markdown） |
| `<dataDir>/logs/` | 运行日志（不含记忆正文） |
| `<dataDir>/models/` | 本地模型权重（首次使用时下载） |
| `<dataDir>/backups/` | 备份文件（可选加密） |

`dataDir` 为空时用 `$DSH_HOME/memweave`；只能在配置文件或 `weave_home`（需人工确认）里改。

- 全量备份为单文件，可加密（AES-256-GCM + scrypt，旁文件记录校验信息）；恢复前自动备份当前库，导入失败整体回滚。
- 升级导致结构变化时先备份再迁移，旧库只加列、不重建表。
